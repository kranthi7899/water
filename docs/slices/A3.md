# Slice A3: Google Workspace connectors (read-only)

Builds on A1 (gate, approvals, audit, store, vault) and A2 (daemon, streaming, one twin). Before A3 the twin could only reach the in-memory `fake_*` connectors; A3 connects it to the CEO's real Calendar, Gmail and Drive/Docs/Sheets, **read-only**, so "what's on my schedule?" and "what did Dana email me?" answer from real data.

## Scope
- **`internal/connectors/google/gapi`**: the shared foundation. One Keychain credential (`water.google/<account>`, compact single-line JSON: `client_id`, `client_secret`, `refresh_token`) backs all three connectors. The access token is cached in memory only, keyed by a hash of the credential, refreshed ahead of expiry or once on a 401. Requests carry the bearer token only to `*.googleapis.com` (or a test's `BaseURL` override). Errors, audit lines, store rows and tool output never contain a token — scrubbed by exact-string match (plain and query-escaped) plus a regex over Google's own token shapes (`ya29.*`, `1//*`, `GOCSPX-*`, `4/*`). `Authorize` runs the installed-app PKCE loopback flow (`water connect google`); `Revoke` undoes it.
- **`gcal`**: `list_events(time_min, time_max, calendar_id?, max?)` → `store.Event`. `singleEvents=true&orderBy=startTime`, paginated.
- **`gmail`**: `list_messages(query?, max?)` and `get_message(id)` → `store.Message`. Bodies are a capped text/plain extraction (falling back to stripped text/html) of the MIME tree.
- **`gdrive`**: `search_files(query?, max?)` and `read_file(id)` → `store.Document`. Docs/Sheets/Slides are read through `files.export` (`text/plain` / `text/csv` / `text/plain`), so no scopes beyond `drive.readonly` are needed.
- Every function is `External: true`: the content came from someone else, so it's untrusted downstream.
- **Manifest**: `twins/ceo/twin.yaml` lists the six functions at level R with per-function rate caps; `auto_allowlist` holds only `gcal.list_events` and `gmail.list_messages` (nothing that summarizes a body runs unattended). The `fake_*` connectors are no longer in the production manifest — they live on in test-only manifests inline in the gate, guards and gateway tests.
- **`water connect google --client-file <path> [--account ceo] [--status] [--revoke]`**: runs the loopback flow (prints the URL, also opens it with `/usr/bin/open` on macOS), stores the credential, and never prints a secret. `--status` forces a live token refresh; `--revoke` revokes at Google and deletes the Keychain entry. `water doctor` reports connected/not-connected (presence only, no network call).
- **Background sync (`internal/sync`)**: a small refresher the daemon starts and stops with itself. Every 10 minutes (configurable: `sync.interval_minutes`), and once right after start, it calls `gcal.list_events` for today through +7 days and `gmail.list_messages` for `newer_than:1d`, through the gate at origin **P2** with **Clean** taint (the arguments are code-built). If no credential is stored it skips quietly, logging one line rather than a stream of denials.
- **Taint fix**: `internal/gateway/daemon.go`'s `handleToolInvoke` now escalates the session's stable tool-proxy token to tainted whenever a model-initiated call's result is `Untrusted` (mirrors the sticky, never-reset escalation `escalateTaint` already documented for A2's context-assembly path, which A2 built but never called from here).
- **Fast-path fix**: `runtime/fastpath.go`'s `scheduleAnswer` and `runtime.StateSummary` used to fetch the 500 newest records by `created_at` and filter by `start_at` in Go — a background sync backfilling an old event could push it past that window. `store.EventsInRange(ctx, s, from, to)` now queries `start_at` directly.

## Out of scope
Incremental sync (`syncToken` / Gmail `historyId`), write functions (`send_email`, `create_event`), and Docs/Sheets-specific APIs beyond `files.export`. Those are A4 (the sync token) and C/D (writes) work.

## Acceptance tests
- Each connector: normalization into store records, pagination, a 401 triggers one refresh then a retry, 429 backoff, `External` flags, and the credential/access token never appear in errors or output.
- A guard test drives a real `gcal.list_events` call through the gate against fake Google HTTP servers and scans the output, the audit log and every store row for the access token.
- The background sync runs against the fake connectors: skips quietly (and logs once) with no stored credential, runs both functions through the gate once connected, and stops promptly when its context is cancelled.
- A model tool call whose result is `Untrusted` leaves the session's token tainted for a later call in the same session.
- `store.EventsInRange` finds an event with an old `created_at` that starts today.
- `go vet ./...`, `go test -count=1 ./...` and `CGO_ENABLED=0 go build ./cmd/water` are green.

## Verify on the Mac
Follow `docs/google-setup.md`, then `water connect google --client-file ...`, `water connect google --status`, `water daemon`, `water ask "what's on my schedule today?"` (fast path, no model call), `water ask "summarize my unread email from today"` (model uses the Gmail tools; the audit log shows the calls), `water audit verify`.
