# Slice A2: daemon, gateway, conversation plane

Run this on branch `feat/ceo-twin`. Read `CLAUDE.md`, `docs/CONTEXT.md` and `docs/EVOLUTION_PLAN.md` first (the A1 log entry explains the gate, permits and approvals you build on). Work unattended. Make the reasonable call instead of asking, and record the notable ones in the plan's log.

## Goal
A single long-running `water daemon` owns the gate, the approval queue, the audit log, the store and the model sessions. Every client talks to it over a local socket. The conversation plane must feel fast on the Claude **subscription** alone. There is no metered API (see CLAUDE.md).

## Phases (commit and push after each)

### 1. Streaming provider and warm session (`internal/backend`)
- **Streaming.** Add a `Streamer` interface: `RunStream(ctx, Request, onDelta func(string)) (Response, error)`.
  - For `ClaudeSubscription`, add `--include-partial-messages` to the existing stream-json args.
  - Parse `stream_event` / `content_block_delta` / `text_delta` lines as they arrive, instead of buffering stdout (today `exec.go` buffers). Keep scrubbed env, process-group kill, timeouts and rate-limit parsing intact.
  - Only use flags that the existing `--help` capability parsing (`exec.go`) reports as present. Degrade to non-streaming otherwise.
- **Warm session.** `WarmSession` keeps one `claude --print --input-format stream-json --output-format stream-json --verbose` process alive and writes each user turn as a stream-json user message on stdin.
  - One turn is in flight at a time.
  - Restart it on crash, on a model or system-prompt change, after N turns, or on `/clear`.
  - If the process dies mid-turn, the turn fails cleanly and the next turn cold-starts.
  - Fall back to per-turn spawn if a warm start fails.
- **Model tiers.** `twin.yaml` gains `models: {fast: ..., strong: ...}`, and the provider picks by tier. Default `fast: haiku` and `strong: ""` (CLI default). If the CLI rejects a model, fall back to the default and log it once.
- **Tests:** deltas arrive in order before the result; cancel kills the process group; a warm session reuses one process across two turns and restarts after a crash; tier selection.

### 2. Runtime and daemon (`internal/runtime`, `internal/gateway`, `water daemon`)
- **`internal/runtime`: the turn loop.**
  - The context assembler builds the system prompt from `twins/ceo/role.md` (phase 4 writes it; tolerate it being missing until then), a compact state summary from the store (today's events, pending approvals), and long-term memory.
  - It streams the reply.
  - For `channel=voice` it also emits whole **sentences** (a sentence splitter in code) and instructs short replies.
- **Deterministic fast paths**, with no model call. A small conservative intent matcher in code answers from the store:
  - today's or tomorrow's schedule
  - pending approvals
  - "what's my brief" (say it's not ready yet if it's missing)
  - Anything it doesn't match clearly goes to the model. Table-test the matcher, including near-misses that must fall through.
- **Model-initiated tool calls go through the gate, which lives in the daemon.**
  - Add a twin mode to `water mcp-serve`. Its tools are the manifest's connector functions, and each call is proxied to the daemon over the socket with a per-turn token. The gate, rate windows and audit all stay in one process.
  - Origin is P0 for a user turn.
  - **Taint is computed in code:** if the turn's context contained any record flagged external/untrusted, every tool call in that turn is tainted.
  - An A-level call creates an envelope in the queue and returns "queued for approval <id>" to the model. It never executes inline.
- **`water daemon`**
  - Serves HTTP over a Unix socket at `~/.water/run/water.sock`: directory 0700, socket 0600.
  - Only one instance runs, enforced by a flock on `~/.water/run/daemon.lock`.
  - Shuts down cleanly on SIGTERM.
  - **Auth:** a bearer token per client. The daemon keeps a 0600 `~/.water/run/clients.json`. The CLI uses a `cli` token created on first start, and `water daemon token new <name>` makes more (for the Shortcut or Swift client later). Unknown or missing token → 401.
- **Endpoints:**
  - `POST /v1/turns`: NDJSON stream of `ack`, `delta`, `sentence`, `approval_required`, `done` and `error` events, with `channel` = cli | voice | text-bar.
  - `GET /v1/approvals`
  - `POST /v1/approvals/{id}/decision`: the body must include the payload hash the client was shown. If the hash doesn't match, it's refused.
  - `GET /v1/state`
  - `POST /v1/tasks/{id}/cancel`
  - `GET /v1/health`
- **Persistence and audit anchoring** (A1 left these open):
  - Persist gate rate windows and usage counts in the store so they survive restarts.
  - Anchor the audit log's last seq+hash in the store on every append. On open, the file's tail must match the anchor, so a truncated tail is detected.
  - `water audit verify`.
  - `water audit repair`: may only drop a single final unparseable (torn) line, and appends a `repair` entry recording it.

### 3. Clients
- `water ask "<text>"` streams one turn to stdout. With `--voice`, it speaks each `sentence` event through the existing `voice.OS` provider (`say`) as it arrives. That is the free interim voice path the macOS Shortcut will call.
- `water approve` lists pending approvals as a numbered menu, using the A1 CLI rendering and the code-generated read-back, then decides them.
- `water chat` becomes a daemon client talking to the one twin. Keep the editor, theme and slash commands that still make sense.
- If the daemon isn't running, clients say how to start it. They do not run an in-process fallback.
- `water daemon install` / `uninstall`:
  - Writes `~/Library/LaunchAgents/com.water.daemon.plist` with KeepAlive and logs in `~/.water/logs/`.
  - Resolves the absolute path of `claude` at install time into the plist's environment (launchd's PATH is minimal).
  - Uses `launchctl bootstrap gui/$UID`.
  - Unit-test the plist generation. Real loading is checked on the Mac.

## Acceptance tests (required)
- A streamed turn over the socket delivers deltas before `done`, against a fake provider.
- A voice-channel turn emits `sentence` events.
- A fast-path schedule question answers from the store with **zero** provider calls.
- Cancel stops an in-flight turn, and the process group is gone.
- A bad or missing token gets a 401.
- The socket is 0600 and a second daemon refuses to start.
- An A-level tool call from the model lands in the approval queue and does not execute. Deciding it with a stale payload hash is refused. Deciding it with the right hash executes it exactly once, and the audit log shows the whole path.
- A tainted turn can't auto-run S-level calls.
- Rate and usage counts survive a daemon restart.
- A truncated audit tail is detected, and `repair` fixes only a torn final line.
- `go vet`, `go test -count=1 ./...` and `CGO_ENABLED=0 go build ./cmd/water` are green.
