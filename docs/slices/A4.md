# Slice A4: incremental sync, fast mail checks, morning brief

Builds on A1–A3 (gate, approvals, audit, store, vault, the daemon, and real read-only Google Calendar/Gmail/Drive connectors). Before A4, `internal/sync` re-fetched a fixed 7-day calendar window and a `newer_than:1d` Gmail search on every single 10-minute tick, and `runtime.FastPath`'s morning-brief branch was a hardcoded "not ready yet." A4 makes sync incremental and fast for mail, and builds the brief.

## Scope
- **`gcal.list_events`** gains an optional `sync_token` argument (mutually exclusive with `time_min`/`time_max`, enforced in `Invoke`). A successful call — either shape — returns `{"events": [...Event], "next_sync_token": "..."}` instead of a bare array, so a caller can persist the cursor from a first, non-incremental call too. A 410 from Google becomes the typed sentinel `gcal.ErrSyncTokenExpired`.
- **`gmail.list_messages`** gains an optional `since_history_id` argument. When present, it walks `users.history.list` (`historyTypes=messageAdded`, paginated, deduped) instead of searching, reusing the existing per-message metadata fetch. Output becomes `{"messages": [...], "history_id": "..."}` for both the query-based and history-based paths. A 404 on a too-old `historyId` becomes the typed sentinel `gmail.ErrHistoryTooOld`; a 404 on an individual message's metadata fetch (deleted between `history.list` and the fetch) is skipped, not treated as the sentinel condition.
- **`internal/store`** migration `0003_sync_cursors.sql`: `sync_cursors(key, value, updated_at)` and `briefs(day, text, created_at)`, with `GetCursor`/`SetCursor`/`DeleteCursor` and `GetBrief`/`SetBrief` (upsert-by-key, mirroring `gatestate.go`). Cursor keys: `gmail:history_id`, `gcal:primary:sync_token`. `briefs` is keyed by local calendar day, `YYYY-MM-DD`.
- **`internal/gate`**: a fix, not new scope — `Invoke`'s credential-redaction step used to discard a failed connector call's error identity (`errors.New(redact(...))`), so `errors.Is` against any connector's sentinel error never matched what `gate.Invoke` actually returned. A `scrubbedError` type (redacted `Error()`, `Unwrap()` returns the original) fixes this without reintroducing the credential into the visible message.
- **`internal/sync`** is rewritten around two independent tickers instead of one: `MailInterval` (default 60s) and `EventsInterval` (default 10m, unchanged). Each tick:
  1. loads its own stored cursor (empty if none),
  2. calls its function with it,
  3. on success, persists whatever cursor field (`next_sync_token` / `history_id`) the raw output carries,
  4. on the connector's expired-cursor sentinel (`errors.Is` through the gate's returned error), deletes the stored cursor and logs it — the next tick is then cursor-less, does a full fetch, and re-seeds a fresh cursor from that response.
  The events tick also drives the morning brief's background precompute (see below) — reusing the existing tick rather than adding a goroutine.
- **`internal/runtime/brief.go`** (new): the morning brief pipeline.
  - Signals computed in code, not by the model: today's events (`store.EventsInRange`), new messages since yesterday (`store.List[store.Message]` filtered by `created_at`), a simple "needs attention" heuristic (excludes bulk/no-reply-looking senders, then looks for a question mark or a short list of urgency/deadline phrases), and the pending-approval count.
  - One `backend.Request` — system prompt instructs the model to only phrase the signal block, never invent a fact outside it — goes through the same `stream`/`Warm`/`Backend` path a normal turn uses.
  - `ComputeAndCacheBrief` is the compute-once entry point: a cache hit (`store.GetBrief` for today) returns instantly with no backend call; a miss computes, caches (`store.SetBrief`), and returns. An in-memory per-day wait map makes concurrent callers for the same day (a background precompute racing an on-demand ask) share one computation instead of each calling the model.
  - Taint is recomputed fresh on every call (not stored alongside the cached text, since the cache may have been computed long before anyone asks) from the same signals, and escalates the session through a new `Env.OnTaint` hook — wired in `gateway/daemon.go` to the existing `escalateTaint` — exactly like a normal turn's tainted context does.
  - `fastpath.go`'s morning-brief branch calls `ComputeAndCacheBrief` — the one deliberate, commented exception to "the fast path never calls the model."
  - Background precompute: the sync loop's events tick checks, once past local `brief.ready_after` (default `07:00`) and only if nothing is cached yet for today, and calls the same function the on-demand path does.
- **`internal/config`**: `sync.mail_interval_seconds` (default 60) and `brief.ready_after` (default `07:00`).

## Owner decision: no Gmail push
Google's Pub/Sub push notifications need a billing account linked to the (free) Google Cloud project, plus one more OAuth re-approval, for about a minute of latency gain over a 60-second poll. The owner explicitly chose fast polling over push (2026-09-24). A4 adds no Pub/Sub, no new OAuth scope, and no new dependency — everything stays inside the existing hand-rolled-REST, GET-only pattern (`gapi.Client.GetJSON`/`GetBytes`/`GetText`).

## Out of scope
Google Pub/Sub push (see above); write functions (`send_email`, `create_event`, C/D territory); anything beyond a simple, explainable, non-model "needs attention" heuristic; long-term memory feeding the brief's signals (it reads the store only).

## Acceptance tests
- `gcal`/`gmail`: the old call shape (no new argument) behaves exactly as before; the new argument triggers the incremental path; the sentinel error surfaces via `errors.Is`; no token ever appears in a new error path; full existing test suites for both packages still pass against the new output shape.
- `internal/store`: cursor and brief round-trip, overwrite, unrelated-key independence, delete-of-absent-key is not an error, concurrent writers don't race or deadlock.
- `internal/sync`: cursor persisted after a successful call and reused on the next; an expired-cursor sentinel clears the cursor and the next tick falls back to (and re-seeds from) a full fetch; two independently-configured intervals actually fire at different rates; skip-quietly-when-not-connected; background brief precompute fires once past `ready_after` and only once per day.
- `internal/runtime`: a cached brief returns instantly with zero backend calls; a first call computes and caches; several concurrent callers for the same day only trigger one backend call; taint escalates when an External record is in the signals and not otherwise.
- `go vet ./...`, `go test -count=1 -race ./...` and `CGO_ENABLED=0 go build ./cmd/water` are green.
